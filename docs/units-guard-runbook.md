# ติดตั้งตัวกันตำแหน่งรถหาย (`supabase-units-guard.sql`)

ผู้ทำ: แอดมินที่เข้า Supabase → SQL Editor ได้ · ใช้เวลา ~10 นาที · **ไม่ต้องหยุดหน้างาน**

## ทำไม
ตั้งแต่ 3 ต.ค. รถที่จอดแล้วถูกเขียนกลับเป็น "รอเข้า ไม่มีตำแหน่ง" เป็นก้อน (NYB2 142 คัน 8 ต.ค., 3D LCB 286 คัน, 60 RAI 80 คัน)
และ 10 ต.ค. รถที่ออกไปแล้วถูกเขียนกลับเป็น "รอเข้า" — มาจากเครื่องที่ยังเป็นแอปเวอร์ชันเก่าและถือข้อมูลเก่า
เราบังคับอัปเดตเครื่องคนอื่นไม่ได้ จึงกันที่ฐานข้อมูล: การเขียนสองแบบนี้จะ **ถูกเมิน (ค่าเดิมคงอยู่)** และ **ถูกจดลง log** พร้อมข้อมูลเครื่อง
ไม่กระทบงานปกติ: Gate-in, Gate-out, Relocation, ยกเลิกขับ, ย้ายยาร์ด, นำเข้ารถรอบใหม่, เพิ่ม/ลบรถ

> ถ้าทีมสลับไปใช้ `yard_units` แล้ว (ดู `docs/cutover-step2.md`) ไม่ต้องทำคู่มือนี้

## ขั้นตอน — **รันทีละขั้น** (คัดลอกเฉพาะส่วนของขั้นนั้นจากไฟล์ แล้วกด Run)

ห้ามรันทั้งไฟล์ในครั้งเดียว: ขั้นที่ 3 จบด้วย error โดยตั้งใจ ถ้ารันรวมกัน การติดตั้งในขั้นที่ 2 อาจถูกย้อนกลับไปด้วย

### ☐ ขั้นที่ 1 — ตรวจ (อ่านอย่างเดียว)
คัดลอกส่วน `ขั้นที่ 1` (คำสั่ง 1a) → Run
- ✅ ต้องเห็นแถว `units_touch_updated_at`
- ❌ ถ้าไม่เห็น → **หยุด** แจ้งกลับ (ต้องรัน `supabase-units-updated-at.sql` ก่อน)
- 📸 ถ่ายภาพผล

### ☐ ขั้นที่ 2 — ติดตั้ง
คัดลอกส่วน `ขั้นที่ 2` ทั้งหมด (ตั้งแต่ `create table if not exists public.unit_guard_log` ถึง `execute function public.units_guard_stale_write();`) → Run
- ✅ ต้องขึ้น "Success" (รันซ้ำได้ ไม่ทับข้อมูล)

### ☐ ขั้นที่ 3 — ทดสอบ (ไม่เปลี่ยนข้อมูลจริง)
คัดลอกส่วน `ขั้นที่ 3` (บล็อก `do $$ … end $$;` ทั้งบล็อก) → Run
- ✅ ต้องขึ้น **error สีแดง** ที่มีข้อความ **"ผลทดสอบ: ผ่านครบ 5/5"** — เป็น error โดยตั้งใจ เพื่อให้ฐานข้อมูลย้อนทุกอย่างกลับเอง
- ❌ ถ้าขึ้น "ไม่ผ่าน" หรือ "ตั้งค่าไม่ถูก" → ถ่ายภาพส่งกลับ (ถ้า "ตั้งค่าไม่ถูก" = รถตัวอย่างเปลี่ยนสถานะไปแล้ว แก้ VIN สองบรรทัดบนของบล็อก)
- 📸 ถ่ายภาพผล

### ☐ ขั้นที่ 4 — ยืนยันว่ารถตัวอย่างไม่เปลี่ยน
```sql
select vin, status, block, "row", slot from public.units
where vin in ('LC0CH6CB8T0128132', 'LC0CE4CB9T4321198');
```
- ✅ `LC0CH6CB8T0128132` ยัง **PARKED · S · 2 · 22** และ `LC0CE4CB9T4321198` ยัง **DEPARTED** (ตามสถานะ ณ 15 ต.ค.)

### ☐ ส่งภาพขั้น 1 และ 3 กลับมา
ผมจะตรวจจากฐานข้อมูลอีกชั้น (อ่านตาราง `unit_guard_log` ได้ = ติดตั้งแล้ว)

## หลังติดตั้ง
- ดูว่ากันอะไรไปบ้าง / มาจากเครื่องไหน: รันส่วน `ขั้นที่ 4: ดูว่ากันอะไรไปบ้าง` ในไฟล์ (หรือให้ผมตรวจให้)
- ถ้า log มีแถว = ยังมีเครื่องเวอร์ชันเก่าเขียนอยู่ → ดู `user_agent` / เวลา เพื่อตามเครื่องให้อัปเดต
- ถ้า log ว่าง 3–7 วันและตำแหน่งไม่หาย = เครื่องเก่าหมดแล้ว

## ถอนกลับ (ถ้าพบว่ากระทบงาน)
```sql
drop trigger if exists units_guard_stale_write on public.units;
```
แค่บรรทัดเดียว ข้อมูลรถไม่ถูกแตะ · ตาราง `unit_guard_log` เก็บไว้ได้
